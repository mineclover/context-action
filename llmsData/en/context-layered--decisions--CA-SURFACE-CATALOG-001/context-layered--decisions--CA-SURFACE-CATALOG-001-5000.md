CA-SURFACE-CATALOG-001: Repository API, Example, and Document Surface Catalog Governance

CA-SURFACE-CATALOG-001: Repository API, Example, and Document Surface Catalog Governance Status: accepted Owner: Framework Architecture & Documentation Governance Related issue/spec: CA-SURFACE-CATALOG-001 (Repository Surface Catalog, Package Boundary Convention, Specification, Issue, and Documentation Management) Context The repository now spans 20 workspace packages (packages/), 72 canonical routes inside example/ (116 total routes including legacy redirects), standalone demos (demos/bolt-style-editor, examples/vanilla-js), 7 package-local examples/ suites, 9 narrative example walkthroughs, 13 root markdown files, bilingual documentation trees, release manifests, and derived TypeDoc/LLMS artifacts. Previously, these surfaces were only discoverable piecemeal across package.json, typedoc.json, example/src/App.tsx, sidebars.ts, and package-boundary-convention.md (where @context-action/lit, @context-action/lit-ui, @context-action/webmcp, and @context-action/template-react were already omitted from the package map). Without a machine-verifiable base specification, new packages, example routes, or unpaired translations drifted silently. Options considered - Manually maintained markdown lists only: Rejected because prose inventories rot immediately when packages, export subpaths, canonical routes, or markdown directories change. - Replacing existing source-of-truth files (package.json, typedoc.json, App.tsx) with a monolithic generator: Rejected because each surface already has an authoritative runtime source (package.json#exports, typedoc.json, example/src/App.tsx, handwritten docs/{en,ko}/); duplicating runtime ownership violates package-boundary-convention.md. - Option 1 (Accepted): Three versioned JSON catalogs under catalog/repository-surface/ verified fail-closed against live disk sources, paired with an authoritative bilingual base guide: Preserves existing runtime/doc sources of truth while enforcing 1:1 structural parity via pnpm verify:surface-catalog. Decision Establish three versioned, machine-verifiable surface catalogs under catalog/repository-surface/ plus bilingual base specifications: - catalog/repository-surface/api-surface.v1.json: catalogs all 20 workspace packages (layer, visibility, stability, exports subpaths, workspace dependencies/peers, typedocEntryPoints, readme, authoritativeDocs, verificationGate). - catalog/repository-surface/example-surface.v1.json: catalogs all 72 canonical example/ routes across 13 semantic groups, standalone demos (demos/bolt-style-editor, examples/vanilla-js), all 7 packages//examples suites, and all 9 paired narrative example docs (docs/{en,ko}/examples/.md). - catalog/repository-surface/document-surface.v1.json: catalogs all 13 root markdown files, managed documentation area

Key points:
• **Manually maintained markdown lists only**: Rejected because prose inventories rot immediately when packages, export subpaths, canonical routes, or markdown directories change.
• **Replacing existing source-of-truth files (`package.json`, `typedoc.json`, `App.tsx`) with a monolithic generator**: Rejected because each surface already has an authoritative runtime source (`package.json#exports`, `typedoc.json`, `example/src/App.tsx`, handwritten `docs/{en,ko}/`); duplicating runtime ownership violates `package-boundary-convention.md`.
• **Option 1 (Accepted): Three versioned JSON catalogs under `catalog/repository-surface/` verified fail-closed against live disk sources, paired with an authoritative bilingual base guide**: Preserves existing runtime/doc sources of truth while enforcing 1:1 structural parity via `pnpm verify:surface-catalog`.
• `catalog/repository-surface/api-surface.v1.json`: catalogs all 20 workspace packages (`layer`, `visibility`, `stability`, `exports` subpaths, workspace dependencies/peers, `typedocEntryPoints`, `readme`, `authoritativeDocs`, `verificationGate`).
• `catalog/repository-surface/example-surface.v1.json`: catalogs all 72 canonical `example/` routes across 13 semantic groups, standalone demos (`demos/bolt-style-editor`, `examples/vanilla-js`), all 7 `packages/*/examples` suites, and all 9 paired narrative example docs (`docs/{en,ko}/examples/*.md`).
• `catalog/repository-surface/document-surface.v1.json`: catalogs all 13 root markdown files, managed documentation areas with explicit `authorityClass` and `pairingPolicy` (`strict-paired`, `tracked-partial`, `single-locale`, `derived`, `not-applicable`), and derived TypeDoc/LLMS outputs.
