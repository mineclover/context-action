## 1. Purpose and Three-Workspace Responsibility Boundaries (Zero-Dependency Principle)

Within the Unified Triad architecture, `context-action` owns **frontend modular state management, the action intent pipeline, and viewport layout hierarchy (Pillar 3 & Pillar 4)**.  
Meanwhile, `.tsp` (TypeSpec) domain contract modeling and TypeScript/OpenAPI code generation are owned by **`oa-sdk` (Pillar 1 & 2)**, and requirement anchor verification (`@evidence`) plus compiler graph/hash lock verification (`@evidenceReview`) are owned by **`ttsc-ex` (Pillar 5)**.

This guide explains **how engineers and AI agents working in `context-action` can autonomously read and pull updates from `ttsc-ex` and `oa-sdk` while preserving zero external domain runtime dependencies in `@context-action/core`, `@context-action/react`, `@context-action/preact`, and `@context-action/preact-ui`**.

| Workspace | Core Single Responsibility | Boundary Rule with `context-action` |
| :--- | :--- | :--- |
| **`context-action`** | • 6-Layer split (`contexts / business / handlers / actions / hooks / views`)<br>• `BusinessActionIntent` vs `LayoutActionIntent` separation (`No Mixed Payloads`)<br>• 3-Tier State Ownership & `Promise.allSettled` parallel aspect hydration<br>• 6-Level layout hierarchy, Two Golden Rules & 4-Tier Semantic Z-Index | `@context-action/*` runtime packages never add direct runtime dependencies on `@typespec/*`, `@oa-sdk/*`, `ttsc`, or `@wrtnlabs/evidence` (**Zero-Dependency preservation**) |
| **`oa-sdk`** | • All `.tsp` domain & governance decorators (`@oa-sdk/typespec-decorators`)<br>• `.tsp` $\rightarrow$ OpenAPI 3.1/3.2 and TypeScript DTO/handler/constant codegen (`oa-gen`)<br>• `x-oa-sdk-trace` + `x-samchon-evidence` JSDoc synthesis | `context-action` applications and examples never parse `.tsp` directly; they consume immutable TypeScript declarations (`dto.ts`, `handlers.ts`, `identity.ts`, `aspect-storage.ts`, `tools.ts`) generated by `oa-sdk` |
| **`ttsc-ex`** | • `@samchon/typespec-evidence` (`@evidence`, `@evidenceExclude`, `## @evidence`)<br>• `ttsc@0.33.1` + `@wrtnlabs/evidence@0.8.0` compiler graph and `@evidenceReview` hash lock gates | Pure functions in `business/` lock generated TS declarations with `@evidenceReview ./generated/dto.ts#... #hash` (or detached `evidenceFiles`) to block spec drift at compile time |

## 3. Five Core Self-Serve Adoption Guidelines for `context-action`

### 3.1 `business/` Policy Hopping and `@evidenceReview` Syntax (`ttsc@0.33.1` / `@wrtnlabs/evidence@0.8.0`)

1. **Locking Generated TypeScript Contract Symbols (`@evidenceReview ./generated/dto.ts#... #hash`)**:
   - Instead of pointing `.ts` directly at `.tsp` files (`@evidenceReview specs/order.tsp#...`), cite and hash-lock the TypeScript declarations synthesized by `oa-gen` or `tsp-evidence pipeline` (`dto.ts`, `handlers.ts`, `identity.ts`, `aspect-storage.ts`, `tools.ts`):
     ```ts
     /**
      * @evidence ./generated/dto.ts#OrderDraftDTO Validates order draft bounds before submission
      * @evidenceReview ./generated/dto.ts#OrderDraftDTO #a1b2c3d4
      */
     export function validateOrderDraft(draft: OrderDraftDTO): ValidationIssue[] {
       // Pure validation logic (zero React/DOM imports)
     }
     ```
2. **Heading-Form Annotations (`## @evidence`, `## @evidenceReview`, `## @evidenceExclude`)**:
   - Use Heading-Form annotations instead of single-line tags when writing multi-paragraph rationales, invariant lists, or checklists:
     ```ts
     /**
      * ## @evidence ./generated/dto.ts#OrderValidationPolicy
      * - Order quantity must remain between 1 and 99.
      * - A valid payment method is required before submission.
      *
      * ## @evidenceReview ./generated/dto.ts#OrderValidationPolicy #a1b2c3d4
      */
     export function evaluateOrderPolicy(draft: OrderDraftDTO): PolicyResult {
       // ...
     }
     ```
3. **Detached Evidence Files (`evidenceFiles`) and File-Header `@evidenceExclude`**:
   - To prevent comment bloat in production code, use **Detached Evidence Files** (`evidenceFiles: ["evidence/**/*.md"]` under `# <unit>` H1 headings) in `evidence.config.json`.
   - For Tier 3 presentation-only files (`views/*.tsx`, etc.), place **File-Header `@evidenceExclude`** at the top of the file to automatically propagate the waiver across all exported declarations in that file:
     ```tsx
     /**
      * @evidenceExclude Tier 3 volatile presentation view component
      */
     export function OrderWorkspaceView() {
       // Render-only component
     }
     ```
   - Run `npx evidence check --only <unit> --context` for fast subtree verification.

### 3.2 Action Intent Domain Separation (`BusinessActionIntent` vs `LayoutActionIntent`)

- Never mix business and layout payloads when designing `contexts/` and `handlers/` (**`No Mixed Payloads`**):
  1. **`BusinessActionIntent`**: Actions that trigger server/storage persistence mutations, core business state machine (`*StateMachine.ts`) transitions, or MCP/Agent tool dispatches.
  2. **`LayoutActionIntent`**: Actions that only control local viewport chrome such as split dock toggles, panel resizing, canvas zoom/pan, or active tab switching.

```ts
// contexts/OrderContexts.tsx — Physical separation of business vs layout intents
export interface OrderBusinessActionIntent {
  updateDraft: Partial<OrderDraftDTO>;
  submitOrder: void;
  resetOrder: void;
}

export interface OrderLayoutActionIntent {
  toggleInspectorDock: { open?: boolean };
  resizeSlotPanel: { panelId: string; widthPx: number };
  setCanvasTransform: { zoom: number; panX: number; panY: number };
}
```

### 3.3 Parallel Aspect Hydration (`Promise.allSettled`) for Decoupled Storage (`@aspectOf`)

- When backend/schema layers (`oa-sdk`) isolate root entities (`@entityRoot`) and feature aspects (`@aspectOf`) under the Anti-God-Table rule, `handlers/` hydrate them in parallel via **`Promise.allSettled`**, gracefully degrading failed optional aspects (`degraded: true` / `null`) without blocking the core view:

```ts
// handlers/useOrderHydrationHandlers.tsx
const [rootResult, fulfillmentAspect, auditAspect] = await Promise.allSettled([
  fetchOrderRoot(orderId),
  fetchOrderFulfillmentAspect(orderId),
  fetchOrderAuditAspect(orderId),
]);

if (rootResult.status === 'rejected') {
  orderStore.setValue(transition(orderStore.getValue(), { type: 'HYDRATION_FAILED' }));
  return;
}

orderStore.setValue({
  root: rootResult.value,
  fulfillment: fulfillmentAspect.status === 'fulfilled' ? fulfillmentAspect.value : null,
  audit: auditAspect.status === 'fulfilled' ? auditAspect.value : null,
  degraded: fulfillmentAspect.status === 'rejected' || auditAspect.status === 'rejected',
});
```

### 3.4 Six-Level Viewport/Layout Hierarchy, Two Golden Rules, and 4-Tier Semantic Z-Index

1. **6-Level DOM/Logical Hierarchy (`6-Level Layout Hierarchy`)**:
   - `L1 app-shell (page)` (`#root`, `isolation: isolate`)
   - $\to$ Parallel siblings: `L2 page-canvas (region)` (`<main>`) & `L3 dock-panel (pane)` (`<aside>`)
   - $\to$ `L4 slot-panel (panel)` (`MenuNode` slice)
   - $\to$ `L5 section-card (section)` (internal control groups)
   - $\to$ `L6 floating-overlay (widget)` (`<dialog>`, `[popover]`, `#overlay-portal`)
2. **Two Golden Rules**:
   - **Golden Rule 1 (Component Slot Decomposition)**: *"Parents (`AppShell`) define parallel slot geometry only; children (`SectionCard`, etc.) encapsulate internal composition."*
   - **Golden Rule 2 (Viewport Geometry Isolation)**: *"Never mount global modals or overlays directly inside a canvas `transform: matrix(...)` subtree; use HTML5 Native Top Layer (`<dialog>`, `popover`) or root portals with inverse scale compensation (`scale(1/zoom)`)."*
3. **4-Tier Semantic Z-Index Scale (Forbidding magic numbers like `9999`)**:

| Tier | Semantic CSS Custom Property | Default | Target Layer & Purpose |
| :--- | :--- | :---: | :--- |
| **Tier 1 (Canvas & Base)** | `--z-base` / `--z-canvas-node` | `1` / `10` | L2 artboard canvas and selection gizmos |
| **Tier 2 (Chrome & Dock)** | `--z-sticky` / `--z-dock` | `100` / `200` | L1 sticky headers and L3/L4 split dock panels |
| **Tier 3 (Overlay & Modal)** | `--z-drawer` / `--z-popover` / `--z-modal` | `400` / `600` / `800` | L6 drawers, popovers, and modal dialog portals |
| **Tier 4 (System Notification)** | `--z-toast` | `1100` | Top-most system toasts and critical alerts |

### 3.5 3-Tier State Ownership and Presentation State Waiver Telemetry

- **The 2-Second State Rule**:
  - State that must survive page reloads or represents a durable domain contract $\to$ **Tier 1 Durable Domain Contract** (`.tsp` model and `@evidenceReview` required)
  - Client derived calculations (`*Result.ts`) and activity events (`*Activity.ts`) $\to$ **Tier 2 Transient Application Logic**
  - Ephemeral UI chrome (`isOpen`, `activeTab`, `isHovered`, `isFocused`) and imperative handles (`ref` Context / `useImperativeHandle` OOP Facades) $\to$ **Tier 3 Volatile Presentation State** (waived from TypeSpec/Evidence)
- When user interaction telemetry is needed for Tier 3 state, bind `@oa-sdk/telemetry` canonical tracking symbols (`UI:EDITOR:...`, 150ms debounced).

## 4. Four-Step Self-Serve Pull Update Workflow and Local Verification

When architecture conventions are updated in `ttsc-ex` or `oa-sdk`, pull and verify them in `context-action` using these four steps:

1. **Step 1 — Inspect Upstream Changes (Discovery)**

2. **Step 2 — Synchronize Paired KO/EN Docs and Agent Skills (Docs & Skill Sync)**
   - Update both `docs/ko/context-layered/` and `docs/en/context-layered/` counterparts ([`triad-evidence-sync-guide.md`](./triad-evidence-sync-guide.md), [`CA-SPEC-EVIDENCE-001.md`](./decisions/CA-SPEC-EVIDENCE-001.md), [`implementation-convention.md`](./implementation-convention.md), [`convention-index.md`](./convention-index.md)) plus the agent playbook skills ([`.agents/skills/context-action-implementation-playbook/SKILL.md`](../../../.agents/skills/context-action-implementation-playbook/SKILL.md) and [`skills/context-action-implementation-playbook/SKILL.md`](../../../skills/context-action-implementation-playbook/SKILL.md)).
   - After editing docs, run `pnpm llms:sync-docs --changed-files ...` to keep `llmsData/` templates and priority metadata synchronized.
3. **Step 3 — Apply to Examples and Business/Handler/View Layers (Layer Application)**
   - Apply intent separation (`BusinessActionIntent` vs `LayoutActionIntent`) in `contexts/`, `@evidenceReview ./generated/dto.ts#... #hash` locks in pure `business/` modules, `Promise.allSettled` parallel aspect hydration in `handlers/`, and file-header `@evidenceExclude` plus 6-Level layout rules in `views/`.
4. **Step 4 — Run `context-action` Local Verification Gates (Local Verification)**
   ```bash
   pnpm docs:management
   pnpm llms:check
   pnpm convention:check
   ```
